4.
   Date/Time: 2026-08-13
   Changes Made:
     - Added support for remote HTTP/HTTPS URLs (including Cloudinary PDF URLs) in "backend/src/utils/pdfExtractor.js".
   Why:
     - The "pdfExtractor" originally only read files from the local filesystem via "fs.readFileSync". To process PDFs stored in Cloudinary, the function now dynamically fetches remote PDFs over HTTP and loads them into a memory buffer before parsing.

5.
   Date/Time: 2026-08-13
   Changes Made:
     - Updated the point ID generation in "backend/services/ai/qdrant_service.js" ("storeChunks") to use "crypto.randomUUID()" instead of sequential indexes based on "metadata.startId".
   Why:
     - To ensure that every vector chunk stored in Qdrant has a globally unique ID (UUID), preventing point collision issues when multiple documents are ingested.

6.
   Date/Time: 2026-08-13
   Changes Made:
     - Replaced local storage of uploaded PDFs with a fully memory-buffered Cloudinary storage.
     - Changed Multer storage in "backend/src/middleware/uploadMiddleware.js" to "multer.memoryStorage()".
     - Updated "uploadNote" in "backend/src/controllers/noteController.js" to upload the memory buffer to Cloudinary, run text extraction on the returned "secure_url", and store the Cloudinary public ID and URL in MongoDB.
     - Added robust failure cleanup in "uploadNote" to delete the uploaded Cloudinary PDF if subsequent MongoDB insertion or text extraction steps fail.
     - Removed the static route serving the local "uploads" directory in "backend/src/app.js".
     - Installed and added "multer" explicitly to "dependencies" in "backend/package.json" to ensure successful installation on production.
     - Deleted the "backend/uploads" directory.
     - To eliminate dependencies on local disk storage, make the app fully cloud-compatible, prevent server file storage leaks, and ensure the app is ready for cloud deployment (e.g., to platforms with ephemeral filesystems like Heroku or Render).
